### Track B — Adaptive memory persistence locked down (`shared/adaptive_memory.py`)
| Change | Detail |
|---|---|
| Atomic saves | `save()` = temp file + `fsync` + `os.replace()`. A crash mid-write can never tear `adaptive_memory.json`; readers see old-full or new-full state. |
| Corrupt quarantine | `_load()` quarantines a corrupt file as `<name>.corrupt-<UTC>` with a loud stderr warning instead of silently clobbering learned state on next save. |
| Config restoration | Saved `half_life_seconds` / `exploration_rate` are restored on load (explicit constructor values win), so run-over-run decay/exploration semantics can't drift between machines or processes. |
| Tests | 6 new in `tests/test_adaptive_memory.py` (accumulate-across-runs, atomic/no-tmp-litter, quarantine, stale-tmp recovery, decay-across-restart, config restore) + 1 end-to-end in `tests/test_cli.py`: two full CLI runs against one memory file; run 2 loads run 1's state and builds on it. |

Live proof: three separate `python3` processes, one file — run 1 wrote
`runs=1 pheromone=4.14`; run 2 loaded exactly that and saved
`runs=2 pheromone=8.28`; a deliberately torn file was quarantined and the live
file rebuilt valid.
