# Strategy — what to actually market

Date: 2026-09-26. Written after auditing the repository's real shape rather
than its perceived shape.

## The premise was wrong, and that changed the answer

The instinct was: *"90-plus-gigabyte codebase full of stuff nobody asked for,
made by someone nobody knows, who is homeless — no one's looking for that."*

Measured:

| | |
|---|---|
| tracked code | **1,612 files, 12 MB** |
| top-level directories | **188** |
| disk used | 73 GB — but the project dirs sum to ~2.4 GB |
| git remote | `BleakNarratives/Snarkie` |
| repository root | `/home/bleaknarratives` — the home directory |

The 90 GB was disk, not code. The codebase is 12 MB, which is a *small* amount
of code — the kind of size that reads as "a focused project," not "a mess."

## The hunch: half right, for a sharper reason

**Right:** nobody can evaluate a home directory with 188 unrelated projects
underneath a `.git` named after one of them. There is no coherent "that" to
point at. The blocker is legibility, not quality and not size.

**Wrong:** the contents are not unsellable. The problem is that the unit of
sale was implicitly the whole repository. It should be one idea.

The correction is cheap: you do not refactor a monster. You choose, and the rest
becomes invisible.

## What was built in response

`cascade-arbitration/` — standalone, stdlib-only, MIT, imports nothing from this
repo and nothing from it imports this repo. Verified from a clean clone.

The claim: **on a small host a local model is not a slower cloud model, it is a
different tool.** Existing routers assume tiers are the same kind of thing
differing in quality, so they order by "best model first." That is backwards for
a 1B model on a 2.6 GB box.

The two defensible ideas:

1. **Resident bytes, not disk bytes.** `llama3.2:1b` is 1.3 GB on disk and
   505 MB resident. A model that cannot stay resident is not slow, it is
   *ineligible* — it thrashes, and the host pays for it. Unmeasured fails closed.
2. **Failure measured, not discovered.** `bench.py` returns
   `local_usable: false` in 20 seconds on this host (1317 MB resident vs 275 MB
   available). The same fact previously cost a 300-second thrash, ~109 GB paged
   out, load average 13, and a process wedged in `D` state.

## What to do with the other 187 directories

**Hide them, don't refactor them.** The allowlist already does this. The
`README.md` now opens by saying what this is and pointing at
`docs/PROJECT_MAP.md`, so a stranger is oriented in ten seconds.

Refactoring 187 projects is unpaid, unfinishable work that destroys provenance
and risks the one thing that works. It is also not what the problem requires.

## The realistic route to "someone is looking for this"

The unit of sale is one idea with one demo, not a repository.

1. **Publish it alone.** A separate repo containing only `cascade-arbitration/`.
   Do not attach it to this workspace. The 188-directory context is a liability
   in a link, not a credential.
2. **Lead with the measurement, not the architecture.** The hook is *"my box
   can't run this, and now I know in 20 seconds instead of 5 minutes."* The
   arbiter is the proof, not the pitch.
3. **Target the audience that already feels this.** People running 1–3B models
   on 8 GB boxes, Chromebooks, Mini PCs, edge and air-gapped machines. They are
   on r/LocalLLaMA and similar. That is a real, growing, currently-unserved
   group; a post that shows `local_usable: false` with real numbers does not
   need a pitch.
4. **The follow-on products are the same idea deeper.** P2-before-P1
   verify-then-trust for on-disk agent state (a poisoned-cache primitive that
   applies to any agent caching state to disk), and drift guards for N-file
   copies. Both are already built and tested in this tree.

## What is genuinely not done

- **Speculative decoding.** The single highest-value remaining inference win
  (2–3x on CPU with a small draft model). Blocked: `ollama 0.34.4` exposes no
  draft flags, and building llama.cpp needs the model *plus* a draft model
  *plus* a link against ~546 MiB available. It is a RAM problem, not a
  research problem.
- **The router `_call_ollama` patch is correct-by-test, never observed
  completing a live call** on this saturated host.
- **Three router copies remain a 3-way feature fork.** `TestCopyDrift` makes
  silent divergence fail loudly; it does not converge them. Converging is a
  merge decision, not a copy, because no copy is a superset.

## The honest ceiling

MoE is the real answer to "better models at small-model cost," and it does not
help here. MoE reduces **FLOPs, not bytes** — a 30B-A3B at 4-bit still needs
~16 GB resident. The constraint on this machine is memory, and the only real
lever is more of it.
